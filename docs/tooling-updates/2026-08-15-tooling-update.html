⚠️ Claude Code v2.1.233 (2026-08-14) — TaskCreate/TaskList 等が新モデルで deprecated / WebFetch TTL 制御追加 / Skill 引数バグ修正

【要注意】TaskCreate / TaskGet / TaskUpdate / TaskList / TodoWrite が新しいモデルでは deprecated になった。 masatoman の scheduled routine（tooling-update-watch 等）がこれらのタスクツールを呼んでいる場合、今すぐ CLAUDE_CODE_ENABLE_TODO_TOOLS=1 を環境変数に設定しないと動作が変わる可能性がある。settings.json または .env で追加して確認を。

CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS 追加。WebFetch のキャッシュ有効期間をミリ秒単位で制御できる。日次 routine で同じ URL を複数タスクが参照するなら CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS=86400000（1日）にするとキャッシュ再利用率が上がり fetch 待ちが減る。

Skill の引数置換バグ修正 — {{args}} が再展開をブロックしていた問題が直った。引数を受け取る Skill を使っているなら今日から挙動が正しくなる。

Claude Opus 5 per-request effort dial (low/medium/high/xhigh/max) — Workflow agent の effort パラメータと直結

2026-07-24 の Opus 5 リリースで追加された機能だが、8月に入って解説記事が増加中。5段階の effort 設定（low/medium/high/xhigh/max）で推論トークン量を1リクエスト単位でコントロールできる。Workflow の agent() の opts.effort がこれに直結。

masatoman の日次 routine（tooling-update-watch・morning brief 等）の scheduled agent に effort: 'low' を明示すると、定型的な情報収集タスクの推論コストが下がり、待ち時間が短縮される可能性がある。MAX 定額なので金銭的メリットはないが、体感速度は変わる。逆に設計・デバッグ・計画立案タスクは effort: 'high' に上げると質が上がる。

デフォルトは medium。effort を未設定のままにするとセッション設定を引き継ぐ — 意識して設定していない Workflow は暗黙的に medium で動いていることになる。

🟡 様子見 — 今週中に tooling-update-watch の scheduled agent に effort: 'low' を試験的に追加して速度比較。品質劣化がなければ採用。
