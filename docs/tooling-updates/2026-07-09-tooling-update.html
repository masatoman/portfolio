🟢 即使う Claude Code CHANGELOG Claude Code v2.1.204 + v2.1.205 — SessionStart hook ヘッドレス修正 / rm -rf 安全化 / --max-turns メッセージ損失修正 / auto-update メモリ最適化

v2.1.203（07-08 フィード掲載）以降に 2 本リリース。masatoman の routine 運用に直結する変更:

  • [v2.1.204] SessionStart hook のヘッドレスセッションでのイベントストリーミング修正。 このフィードエージェント自体が SessionStart hook を使うヘッドレス実行のため、 hook の発火タイミング or 通知が欠落していた可能性がある。今日以降は正常化。
  • [v2.1.205] auto mode が未解決変数の rm -rf 実行前に確認を求めるように。 rm -rf $UNDEFINED_VAR/ 系のコマンドを auto モードが誤って実行してファイルを消すリスクが低減。 routine スクリプト内で変数展開が壊れていても即座に破壊されなくなる。
  • [v2.1.205] --max-turns 上限でターンが終了した際のメッセージ損失を修正。 max-turns で打ち切られたとき最後のメッセージが消えていたバグ。 ルーティンが最大ターン数に達した場合の出力が完全に記録されるようになる。
  • [v2.1.205] SendMessage で再開した後の background agent ステータス表示修正。 エージェントの状態追跡が正確になり、claude agents 画面の表示ずれが解消。
  • [v2.1.205] auto-update 時にバイナリをストリームでディスク書き込みしてメモリ使用量を最適化。 自動アップデートのメモリスパイクが抑制される。
  • [v2.1.205] その他: --json-schema の無効スキーマ時に非構造化出力が出ていた問題修正 / auto mode がセッションのトランスクリプトファイルを改ざんできないルールを追加 / Windows worktree 削除時に NTFS junction 外のファイルを消すバグを修正
今日やること: claude update で v2.1.205 に更新。 SessionStart hook 修正（v2.1.204）は今朝の実行からすでに効いている可能性あり（このフィード自体が対象）。 rm -rf 安全化と max-turns メッセージ損失修正は routine の信頼性に直結。

1 月にデスクトップ専用でリリースされた Claude Cowork が、7/7 から Max プランユーザー向けに Web (claude.ai ホーム) と iOS・Android アプリのサイドバーで利用可能になった。

  • Cowork 使用量 2 倍特典を 8/5 まで延長。 beta 期間中は通常比 2 倍のクレジットで使える。
