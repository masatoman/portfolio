Claude Code v2.1.207 — hook セキュリティ修正 + ターミナル凍結バグ解消 (July 11)

v2.1.207 (2026-07-11 00:52 UTC リリース) の主要変更点:

① Plugin hooks セキュリティ修正: shell-form コマンド内の ${user_config.*} 変数展開を拒否するよう変更 (shell injection 防止)。
② ターミナル凍結バグ修正: 長いリスト・テーブル・コードブロック・段落をストリーミング中に Claude Code がフリーズする現象を解消。
③ カスタムランチャー保護: auto-updater が ~/.local/bin/claude のカスタム起動スクリプトを上書きしてしまうバグを修正。
④ Windows 60秒ハングガード: AWS 認証情報の解決が止まった場合に無限ハングせず 60 秒でタイムアウト。

🟢 即確認 — UserPromptSubmit hook など CLAUDE.md のフック設定に ${user_config.*} 変数を使っていた場合、アップデート後に動作が変わる。/doctor を打って設定を一発チェックしてから次のルーティン実行を回すのが安全。長コンテンツのフリーズ問題が消えたことで Workflow エージェントの出力が長くなっても詰まらなくなった。

Destructive Command Guard (Dicklesworthstone) — エージェントの危険 git/shell コマンドを Rust でブロック (GitHub Trending, 2.8k stars)

AI エージェントが git reset --hard・rm -rf・force push などの破壊的コマンドを実行しようとした際に Rust レベルでインターセプトしてブロックするツール。GitHub Trending で急浮上中。

🟡 様子見 — Claude Code の auto mode が v2.1.202 以降すでに「未解決変数を含む rm -rf には確認を入れる」「destructive git コマンドをブロック」を内包済み。これを追加すると保護レイヤーが二重になり設定管理が複雑化する。GitHub Actions や Claude Code 外の自動化スクリプトで同等の安全網が必要になった時に再評価。今すぐは不要。
→ GitHub: Dicklesworthstone/destructive_command_guard
