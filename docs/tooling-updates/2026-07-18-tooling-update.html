Claude Code /fork — 現セッション保持のまま会話を別バックグラウンドセッションへ分岐

/fork コマンドを実行すると、現在の会話の完全なコピーを新しいバックグラウンドセッションに送り込む。元のセッションは止まらず、分岐先は claude agents の独立した行として並走する。

この routine のように「本番動作を維持しながら実験的なプロンプト変更を試したい」場面で直接使える。現在の routine を /fork して variant を走らせ、結果を比較してから本番に反映するサイクルが可能になる。バックグラウンドエージェントとの組み合わせで並列テストの工数が大幅に下がる。

Claude Code セッション暴走防止ガード — WebSearch 上限 + Subagent 生成上限を環境変数で設定可能に

CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION（デフォルト 200）と CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION（デフォルト 200）が追加された。設定値を超えるとループが止まる。バックグラウンドエージェントも同様に自動アップグレード（= 起動時の stale バージョン問題が解消）。

この tooling-update-watch routine は毎回 WebSearch を 5〜8 回発行する。環境変数を明示設定しておくと、将来的に routine のバグでループした際のコスト爆発を防げる。.env や Claude Code の設定ファイルに CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION=50 を入れておけば routine 分には十分な余裕がある。

token-diet 系「AI コーディングコスト削減ツール」— MAX プラン運用者には逆効果な思考法

token-diet（2026-07-03 公開）をはじめ、AI コーディングのトークン消費を削減するための各種ツール・Playbook が急増中。「1 developer-day あたり $15 → $3〜5 に下げる」「プロンプトキャッシュ＋安いモデル切り替え」等を訴求している。Microsoft・Uber での $500〜2,000/engineer/month 超過事例を背景に需要が高まっている。

masatoman は MAX プラン定額（利用量に関わらず固定料金）で運用中。この文脈でトークン節約に時間をかけることは、定額の価値を自ら毀損する行為になる。「コスト削減」ではなく「同じ時間でより多くのサイクルを回す」が正しいレバーで、節約ではなく活用量を最大化するのが正しい方向。
