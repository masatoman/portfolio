MemoryCustodian v0.9.1 ── Claude Code 対応のリポジトリネイティブ記憶システム

コーディングエージェント向けのプロジェクト記憶ツール。意思決定・制約・却下したアプローチ・ファイル境界を リポジトリ内のMarkdownとして保存し、エージェントが必要なコンテキストだけを選択的に読み込む。 Claude Code 対応で ./install.sh claude を実行するとスキルとして即組み込み可能。 Python 標準ライブラリのみで動作、外部サービス不要、オフライン完結。 7/12〜19 の Build Week で v0.7.0 → v0.9.1 に大幅更新。

masatoman の現在の CLAUDE.md + ~/.claude/projects/…/memory/ 体制は人間が手動メンテする「静的記憶」。 MemoryCustodian は Claude Code 自身が実行中に判断・却下ルートをリポジトリへ書き込む「動的記憶」になる。 既存のメモリアーキテクチャとの整合性確認（ファイル命名規則の競合がないか）を先に行うこと。 整合が取れるなら、portfolio の判断ログ蓄積に今週中に試す価値あり。

🟡 様子見 ── 既存 CLAUDE.md + memory/ との競合チェックが先。整合 OK なら 🟢 に格上げ可能。Claude Code スキルとして組み込めるのは強み。 → waittim/MemoryCustodian (GitHub) → Product Hunt ページ

usekaneo/kaneo ── 「要るものだけ」ミニマルOSSプロジェクト管理ツール（GitHub Trending +760★/日）

"All you need. Nothing you don't." をコンセプトにした軽量 OSSのプロジェクト管理ツール。 本日 GitHub Trending で +760★ を記録し急上昇。 Next.js + Go + SQLite ベースでセルフホスト可。Linear・Jira の代替として クリーンな UI とシンプルな構造が特徴。

masatoman のひとり開発フェーズでは GitHub Issues + Claude Code /todo で十分カバーできる。 ただし将来 MVP 投入後に複数顧客の進捗を追う段階になった場合、 セルフホストで顧客データを外部クラウドに出さない PM ツールとして候補になる。 現時点ではスター急上昇の理由を確認する程度でよい。

🟡 様子見 ── 今はGitHub Issues + Claude Code で十分。MRR スケール後、工務店案件ごとの進捗管理が必要になった段階で再評価。README だけ眺める程度で OK。 → usekaneo/kaneo (GitHub)
